# Feature Engineering Module

## Real-Time-UPI-Fraud-Detection-System

### Module Overview

The Feature Engineering Module transforms raw UPI transaction data into meaningful behavioral features that help the anomaly detection model distinguish normal user behavior from potentially fraudulent activity.

Unlike traditional fraud detection systems that rely on manually defined rules, this project uses machine learning to learn the normal transaction fingerprint of each user. The quality of these behavioral features directly impacts the performance of the Isolation Forest anomaly detection model.

This module processes synthetic UPI transaction data generated by the Data Generation Module and creates fraud-indicative features that capture user spending habits, transaction velocity, merchant interaction patterns, location behavior, and temporal characteristics.

---

# Business Problem

Fraudulent transactions often appear normal when viewed individually.

For example:

| Transaction | Amount |
| ----------- | ------ |
| Genuine     | ₹2,000 |
| Fraudulent  | ₹2,000 |

Looking only at the transaction amount makes detection difficult.

However, when behavioral context is considered:

* User normally spends ₹300–₹500
* Transaction occurred at 2:30 AM
* Merchant is new
* Location is unfamiliar
* Device has never been used before

the transaction becomes suspicious.

The Feature Engineering Module creates these behavioral indicators for anomaly detection.

---

# Module Objectives

The module is designed to:

1. Clean and validate transaction data.

3. Generate temporal fraud indicators.
4. Calculate spending pattern metrics.

# Temporal Feature Engineering

Transaction time is a strong indicator of user behavior.

The module extracts:

| Feature                | Description                   |
| ---------------------- | ----------------------------- |
| transaction_hour       | Hour of transaction           |
| day_of_week            | Day number                    |
| month                  | Month                         |
| weekend_flag           | Weekend indicator             |
| night_transaction_flag | Late-night activity indicator |

Example:

| Timestamp        | Hour | Weekend |
| ---------------- | ---- | ------- |
| 2026-03-05 22:15 | 22   | 0       |

---

# Amount-Based Features

These features compare a transaction against a user's historical spending pattern.

### Features Created

| Feature            | Description                |
| ------------------ | -------------------------- |
| transaction_amount | Current transaction amount |
| user_avg_amount    | User's average amount      |
| amount_deviation   | Difference from average    |
| amount_ratio       | Amount relative to average |
| amount_zscore      | Standardized deviation     |

Example:

```text
Current Amount = ₹10,000

User Average = ₹800

Amount Ratio = 12.5
```

Large deviations often indicate suspicious behavior.

---

# Transaction Velocity Features

Fraudulent transactions often occur in rapid succession.

The module creates:

| Feature                 | Description                     |
| ----------------------- | ------------------------------- |
| transactions_last_hour  | Count within previous hour      |
| transactions_last_day   | Count within previous day       |
| transaction_gap_minutes | Time since previous transaction |
| velocity_score          | Activity intensity measure      |

Example:

```text
Normal User:
5 Transactions / Day

Suspicious User:
20 Transactions / 10 Minutes
```
